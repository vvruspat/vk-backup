# VK Backup

Десктопное приложение на Tauri 2, React, TypeScript и Radix UI. Сохраняет доступные данные ВК непосредственно на компьютер пользователя. Музыка не включена.

## Возможности

- Фотоальбомы, включая системные, с выбором целого альбома или отдельных фотографий на всех страницах.
- Видео и видеоальбомы; документы в исходном формате.
- Личный аккаунт и сообщества, где пользователь администратор (`groups.get`, `filter=admin`). Можно выбрать несколько источников в одной очереди. У сообществ используется отрицательный `owner_id`.
- Профиль, сведения о сообществе, стена, список друзей и доступная переписка в JSON. Переписка экспортируется с полной пагинацией истории каждого доступного диалога.
- Выбор папки системным диалогом, общий прогресс и прогресс текущего файла, скорость, пауза, продолжение, отмена, отчёт о пропусках.
- Повторные запуски: размер и SHA-256 каждого готового файла проверяются; целые файлы пропускаются, повреждённые скачиваются заново. JSON обновляется. Незавершённый текущий файл при новом запуске скачивается заново.
- Предварительная запись владения файлом в manifest позволяет восстановиться после закрытия процесса между сохранением файла и записью результата. Блокировка папки не позволяет двум экземплярам писать один архив одновременно.
- `index.html` — локальная галерея без внешних запросов; файлы и описания по альбомам, `manifest.json` с результатами и предупреждениями.

## Запуск и сборка

Нужны Node.js 22.12+ (или 24+), актуальный стабильный Rust и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/). Проект проверен с Rust 1.99.

```sh
npm ci
npm run tauri dev
```

```sh
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings
npm run tauri build
```

Установщики появляются в `src-tauri/target/release/bundle`. На macOS можно собрать только приложение: `npm run tauri build -- --bundles app`.

Если глобальная установка Rust принадлежит администратору, можно создать локальную установку в игнорируемой папке `.toolchain`. Обёртка `npm run tauri` обнаруживает её автоматически:

```sh
RUSTUP_HOME="$PWD/.toolchain" rustup toolchain install stable --profile minimal
RUSTUP_HOME="$PWD/.toolchain" rustup component add rustfmt clippy
RUSTUP_HOME="$PWD/.toolchain" cargo test --manifest-path src-tauri/Cargo.toml --locked
```

В `.github/workflows/desktop.yml` настроены проверки для macOS, Windows и Ubuntu, в `.github/workflows/release.yml` — установщики и публикация релизов. Локально проверена macOS Apple Silicon; сборка и тесты Windows/Linux выполняются в GitHub Actions. Запуск интерфейса и скачивание медиа на Windows/Linux требуют отдельной проверки на этих системах.

## Подключение ВК

Вход выполняется через настроенный VK Mini App **54816788**. В форме входа нет технических полей и ручного ввода токена. Сервисных ключей и токенов в исходниках нет.

1. Откройте «Подключить ВК».
2. Нажмите «Войти через ВК».
3. Подтвердите доступ к фото, видео и сообществам в открывшемся окне ВК.
4. Вернитесь в приложение: подключение завершится автоматически. Во время ожидания доступны отмена и свёрнутая подсказка с кодом на случай, если ВК попросит его вручную.

Вход запрашивает права `photos video groups`. Дополнительные разделы требуют отдельных разрешений, если ВК предоставляет их приложению. Каждый раздел проверяется отдельно; отказ отображается в интерфейсе.

Чтобы собрать приложение с другим публичным ID Mini App, скопируйте `.env.example` в `.env.local` и заполните `VITE_VK_MINIAPP_ID`. **Не помещайте токены или секреты в VITE-переменные:** они включаются в интерфейс при сборке.

Токен не хранится в localStorage, файлах или настройках. Он находится в памяти Rust до выхода/закрытия приложения. Пароль вводится непосредственно на сайте ВК в системном браузере. Ожидание входа прекращается через пять минут; при истечении токена нужно повторить вход.

### Подключение через VK Mini App

Mini App используется как мост для получения пользовательского токена VK API. Он открывается внутри ВК; бэкап и скачивание файлов выполняет десктопное приложение.

1. В настройках отдельного VK Mini App **54816788** укажите адрес веб-приложения **`https://vk-backup.whitesquirrel.digital/miniapp`**. Это адрес самого Mini App, а не redirect URL приложения VK ID. Для проверки до публикации аккаунт должен иметь доступ к запуску этого Mini App.
2. В VK Backup откройте «Подключить ВК» или «Настройки» → «Переподключить ВК». ID Mini App настроен в сборке.
3. Нажмите «Войти через ВК». Откроется `https://vk.com/app54816788#pair=…`. Если ВК не передаст код в Mini App, раскройте «ВК попросил код подключения?» в VK Backup, скопируйте код и вставьте в форму внутри Mini App.
4. Подтвердите запрос `photos,video,groups` в окне ВК. Mini App передаст зашифрованный результат; десктопное приложение проверит реальную доступность этих методов и принадлежность токена аккаунту. При расширении существующего подключения требуется тот же аккаунт. При отказе прежняя сессия сохраняется.

Передача использует одноразовую пару ключей P-256, ECDH, HKDF-SHA256 и AES-256-GCM. Сервер хранит только открытый ключ получателя, параметры подключения и зашифрованный ответ в памяти не более пяти минут. Закрытый ключ и отдельный секрет получения остаются на компьютере. Получение ответа одноразовое; отмена удаляет ожидающее подключение. Токен не попадает в URL, журналы, localStorage или файлы сервера. Страница и официальный VK Bridge SDK поставляются локально одним пакетом без загрузки сторонних скриптов при входе.

Мост не увеличивает права, которые разрешает ВК данному Mini App. 11 октября 2026 года вход через Mini App 54816788 проверен с реальным аккаунтом: доступны личные фотоальбомы, видеоальбомы и администрируемые сообщества; проверено сохранение фото из личного аккаунта и группы и короткого видео. Mini App не выдаёт refresh token в этом сценарии: при истечении пользовательского токена потребуется повторить вход.

### Публичная страница возврата

VK ID требует HTTPS для зарегистрированного redirect URL. Статическая страница из `auth-relay/public` принимает `code`, `state` и `device_id`, удаляет их из истории вкладки и возвращает браузер на фиксированный `http://127.0.0.1:47851/callback`. Приложение должно быть открыто на том же компьютере. Обмен кода и обновление токена выполняет Rust с тем же HTTPS redirect URI и локальным PKCE verifier. Публичная страница не получает access/refresh token, не содержит аналитики, cookies или внешних ресурсов. HTTPS-сервер видит одноразовый код в запросе; журналы запросов отключены и в nginx, и для выделенных маршрутов Traefik. PKCE verifier остаётся в приложении.

Размещение на существующем сервере с Coolify/Traefik:

1. Создайте DNS-запись `A vk-backup → 13.140.153.191` в зоне `whitesquirrel.digital`.
2. Скопируйте каталог `auth-relay` на сервер, например в `/opt/vk-backup-auth`.
3. В этом каталоге запустите `docker compose up -d`. Конфигурация использует существующую сеть `coolify`, входы Traefik `http`/`https` и resolver `letsencrypt`.
4. Проверьте `https://vk-backup.whitesquirrel.digital/`, `/callback`, `/miniapp` и `/bridge/health` с действительным сертификатом. Для `/miniapp` разрешено встраивание только в страницы ВК; для остальных страниц встраивание запрещено.

Nginx обслуживает статические страницы, отдельный контейнер Node.js — одноразовые подключения `/bridge/`. Контейнеры не публикуют собственные порты хоста, работают без root, с файловой системой только для чтения. Сервер подключения ограничивает размеры запросов, число активных подключений и скорость их создания. Журналы запросов отключены. Изменив `miniapp-entry.js`, пересоберите `npm run build:miniapp` и обновите файлы `public` на сервере; после изменения nginx выполните проверку конфигурации и перезагрузку nginx. Для другого домена нужно одновременно поменять `REDIRECT` в `src-tauri/src/auth.rs`, `BASE` в `src-tauri/src/miniapp.rs`, проверку Origin в сервере подключения, подсказки интерфейса и маршруты Traefik.

## Видео

Сначала выбирается наибольший доступный `mp4_*` из VK API. Если прямого файла нет, выполняется дополнительный запрос `video.get` с идентификатором записи и её ключом доступа. Установленный на компьютере [yt-dlp](https://github.com/yt-dlp/yt-dlp#installation) используется автоматически, если пользователь не выключил настройку «Видео через yt-dlp». Выбор сохраняется между запусками. Приложение не устанавливает загрузчик автоматически.

Для yt-dlp сначала используется обычная страница `https://vk.com/video<owner_id>_<id>` с ключом доступа, если ВК его выдал. Ссылка встроенного плеера проверяется только при неудаче: плеер может отклонять скачивание, хотя обычная страница того же видео работает. Ошибки загрузчика показываются без подписанных ссылок.

yt-dlp должен быть доступен в PATH; на macOS также проверяются `/opt/homebrew/bin/yt-dlp` и `/usr/local/bin/yt-dlp`. Используется лучший готовый MP4 с видео и звуком (`best[ext=mp4]`), поэтому отдельный ffmpeg не нужен; это может быть ниже максимального качества, доступного только отдельными дорожками. При паузе процесс прекращается и после продолжения возобновляет временную загрузку.

Видеозаписи, требующие дополнительной браузерной сессии, DRM, неподдерживаемого формата или прав, могут остаться недоступными. Cookies браузера автоматически не извлекаются. Такие записи не считаются сохранёнными и включаются в отчёт.

## Структура архива

```text
VK Backup - id123/
  Мой аккаунт/id123/
    Фото/Название альбома [123_photos_456]/
      album.json
      Название [123_789].jpg
      Название [123_789].metadata.json
    Видео/...
    Документы/...
    Данные/...
  Сообщества/club456/
    Фото/...
    Видео/...
    Документы/...
    Данные/...
  index.html
  manifest.json
  .backup.lock
```

Имена совместимы с Windows, macOS и Linux. Файлы сначала записываются во временный `.part`, после полного получения перемещаются на место. Ошибка HTTP, HTML вместо файла, оборванное соединение и неполная длина не дают отметить файл готовым. Внутри архива запрещены символические ссылки и выход за пределы выбранной папки. Токены, ключи доступа и подписанные ссылки на видеоплеер удаляются из экспортированных метаданных.

## Границы бэкапа

При реальной проверке 11 октября 2026 года вход владельца через приложение VK ID 54816594 предоставил профиль и список из 118 видео. `photos.getAlbums` и `groups.get` вернули код 1051 с сообщением `Method is not available for this profile type: method is unavailable with current profile type`. `video.getAlbums` вернул код 8502 с сообщением `Invalid scope`. В списке видео не было прямых MP4-ссылок. Это ограничение фактически выданного доступа; успешный вход не означает, что фотоальбомы и администрируемые сообщества доступны. Приложение показывает код и очищенное сообщение ВК. Требуется пользовательский токен VK API с разрешёнными методами для чтения этих разделов; изменение одного текста `scope` не подтверждает выдачу этих прав.

После исправления выбора видеостраницы проверено скачивание двух роликов прямо в нативном приложении с установленным yt-dlp: 5,13 с (720×1280, H.264) и 31,48 с (1080×1920, H.264 + AAC). Бэкап завершился без предупреждений; размеры и SHA-256 файлов совпали с manifest.json. Повторный запуск пропустил ранее сохранённый ролик и скачал второй. Эти результаты подтверждают проверенные ролики, но не все приватные видео или форматы ВК.

После подключения через Mini App 54816788 тот же аккаунт получил доступ к 767 личным фотографиям, видеоальбомам и списку из 20 администрируемых сообществ. В Antillia загружен каталог из 55 фотоальбомов с 1 698 фотографиями. В отдельной проверке нативное приложение сохранило одну личную фотографию (531×857), фотографию сообщества «Рок-мюзикл \"Меч в камне\"» (987×600) и MP4 длительностью 5,13 с (720×1280, H.264) в один архив с раздельными каталогами источников. Все три записи завершены без ошибок; размеры и SHA-256 совпали с manifest, форматы файлов проверены. Secret key и сервисный ключ для этого сценария не использовались.

Это экспорт доступных приложению данных, а не гарантированная копия всего внутреннего хранилища ВК. Архив не включает музыку, удалённые данные, Stories, комментарии и обсуждения, участников сообществ или недоступные приватные записи. Вложения стены и переписки сохраняются **как метаданные в JSON**, их бинарные файлы автоматически не обходятся. Для медиа выбирайте фотоальбомы, видео и документы.

Вход через Standalone, дополнительные разрешения `docs`, `wall`, `friends`, `messages` для Mini App и реальные приватные видео остаются непроверенными. Локальные тесты используют изолированный сервер и демонстрационные данные; результаты реальной проверки выше относятся к проверенному аккаунту, сообществам и файлам.

## Демонстрация интерфейса

```sh
npm run dev
```

Откройте `http://localhost:1420/?demo=1`. Это явно помеченная симуляция: SVG-иллюстрации, демонстрационный аккаунт и сообщества. Файлы не скачиваются. Обычный веб-предпросмотр и десктопная сборка не подменяют данные ВК демонстрацией.

## Источники интеграции

- [Официальная схема VK API 5.199](https://github.com/VKCOM/vk-api-schema): параметры фотоальбомов, видео, документов и сообществ.
- [Официальный VK ID SDK](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts): PKCE, state, device_id, обмен кода и обновление токена.
- [Официальный VK Bridge](https://github.com/VKCOM/vk-bridge): взаимодействие Mini App с клиентом ВК и запрос пользовательского токена.
- [Tauri 2](https://v2.tauri.app/): нативные команды, системные диалоги, события и ограничения возможностей окна.

## Сборки и релизы

Исходный код: [vvruspat/vk-backup](https://github.com/vvruspat/vk-backup). Готовые установщики: [GitHub Releases](https://github.com/vvruspat/vk-backup/releases).

На каждый push в `main` и pull request выполняются тесты, сборка интерфейса, проверка форматирования и Clippy для macOS, Windows и Ubuntu.

Workflow `Release desktop apps` запускается при push тега `v*`, публикации релиза в GitHub или вручную из Actions с указанием существующего тега. Версия тега должна совпадать с `package.json`, `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`. Для следующего релиза обновите эти версии и соответствующие lock-файлы, закоммитьте изменения, затем:

```sh
git tag v0.1.1
git push origin main v0.1.1
```

Автоматически собираются macOS Apple Silicon и Intel (`.dmg`), Windows x64 (`.exe`, `.msi`), Ubuntu x64 (`.deb`, `.AppImage`). При запуске по тегу сначала создаётся черновик; он публикуется только после успешной сборки всех четырёх вариантов и проверки наличия установщиков. Также прикладывается `SHA256SUMS.txt`. Неудачную сборку можно повторить через Actions; уже опубликованный релиз получает файлы без изменения его описания.

Для публикации используется встроенный `GITHUB_TOKEN` с правом `contents: write`; отдельный персональный токен и ключи ВК в секретах GitHub не нужны. Actions закреплены на конкретных коммитах. macOS использует ad-hoc подпись без нотарификации Apple, Windows собирается без подписи издателя. Сервер Mini App развёртывается отдельно; релиз десктопа не меняет его конфигурацию.
